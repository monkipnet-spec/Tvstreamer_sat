TVStreammerSAT5 202.44

HLS input recovery fixes based on 202.43:
- souphttpsrc/curlhttpsrc HLS playlist and segment downloads use infinite internal retries when supported
- GStreamer 1.26+ retry backoff is bounded (0.25 factor, 2 s maximum)
- HLS GST_MESSAGE_ERROR no longer permanently stops the channel; it schedules an automatic pipeline rebuild
- HLS EOS no longer permanently stops a live channel; it schedules an automatic pipeline rebuild
- HLS no-data watchdog keeps the validated 15 s threshold but now rebuilds the same primary HLS source when no backup is configured
- HLS is excluded from generic continuity/CPU-overload recovery to avoid false rebuilds on legitimate segment continuity changes
- recovery retries are bounded to 5 s after a failed rebuild and the bus monitor remains alive even if a rebuild temporarily has no bus
- generic non-HLS input-loss timeout remains 6 s; SRT startup and HLS no-data thresholds remain 15 s
