# TVStreamer satellite v78 — изменения

## Исправлено отображение ошибок запуска

- `POST /api/start-stream` больше не отвечает `ok` безусловно.
- Ошибка, которую возвращает `StreamManager::startStream()` / `restartStream()`, возвращается браузеру в JSON.
- В веб-интерфейсе добавлено отдельное окно ошибки с полным сообщением GStreamer.
- После успешного ответа Start выполняются дополнительные проверки состояния через 2.5 и 5.5 секунды, чтобы показать асинхронные ошибки, которые пришли на GStreamer bus уже после перехода в `PLAYING`.

## Исправлено завершение GStreamer pipeline

- Добавлен единый `stopPipelineAndWait()` с переводом pipeline в `GST_STATE_NULL` и ожиданием завершения асинхронного перехода.
- Перед остановкой основного pipeline GStreamer bus переводится в flushing mode, затем завершается `busThread`, и только после этого освобождаются pipeline/bus.
- Начальный доступ `monitorBus()` к таблице потоков защищён `managerMutex`.
- Аналогично усилена очистка shared-DVB, satellite relay, SRT relay, probe и restart pipeline.

Это направлено на устранение гонки teardown, соответствующей журналу с повторяющимися `gst_poll_wait`, `GST_IS_TASK`, последующим `G_IS_OBJECT` и `Segmentation fault`.

## Conditional Access / Phoenix

В исходной v77 поле `conditional_access_reader` только сохраняется и отображается в интерфейсе. Оно не передаётся в `StreamManager`, не открывает `/dev/ttyUSB*` / `/dev/ttyACM*`, не выполняет ECM/CW обмен и не участвует в descrambling.

Поэтому в v78 **не добавлен фиктивный «кеш карты»**: без CA backend такой кеш не может декодировать поток. Если указан Phoenix/serial reader, Start теперь явно показывает предупреждение, что выбранное устройство не используется pipeline.

Для многоканальной работы требуется отдельный авторизованный CA backend/broker, который умеет работать с вашей картой/CAM и выдавать приложению уже разрешённый результат декодирования или предоставлять поддерживаемый CA API. TVStreamer затем можно подключить к такому логическому provider вместо прямой привязки каждого канала к физическому serial reader.

## Проверка сборки

В среде, где подготовлен этот патч, отсутствуют development-пакеты `gstreamer-1.0`, `gstreamer-app-1.0` и `gstreamer-mpegts-1.0`, поэтому полная компиляция здесь не была завершена. На целевой Ubuntu необходимо выполнить обычную сборку проекта после установки зависимостей из `install_deps.sh` и проверить запуск на DVB-оборудовании.
